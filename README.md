# LightGlue Minimal Matching Demo

This repository provides a minimal image matching demo based on **LightGlue** and **SuperPoint**.

The goal of this project is not to reproduce the full LightGlue paper results, but to build a clear and beginner-friendly pipeline for understanding local feature extraction, feature matching, and match visualization in computer vision.

## 1. Project Goal

This project aims to run a minimal image matching pipeline:

```text
Two input images
↓
SuperPoint extracts keypoints and descriptors
↓
LightGlue matches local features between two images
↓
Matched indices are stored in matches
↓
Matched point coordinates are obtained as points0 and points1
↓
The matching result is visualized and saved
```

Through this project, I want to understand:

* How SuperPoint extracts local features
* How LightGlue produces feature matches
* What `matches`, `points0`, and `points1` mean

## 3. Environment Setup

Create a conda environment:

```bash
conda create -n lightglue python=3.10 -y
conda activate lightglue
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

If `lightglue` cannot be imported, install the official LightGlue repository manually:

```bash
git clone https://github.com/cvg/LightGlue.git
cd LightGlue
python -m pip install -e .
```

Then check whether LightGlue is installed successfully:

```bash
python -c "from lightglue import LightGlue, SuperPoint; print('LightGlue import success')"
```

## 4. Prepare Images

Put two images into the `images/` folder:

```text
images/
├── image0.jpg
└── image1.jpg
```

The two images should contain overlapping visual content, such as the same building, room, object, or scene from different viewpoints.

## 7. Key Variables

| Variable            | Shape / Type | Meaning                                       |
| ------------------- | ------------ | --------------------------------------------- |
| `image0` / `image1` | `[3, H, W]`  | Input images represented as PyTorch tensors   |
| `feats0` / `feats1` | `dict`       | Feature dictionaries extracted by SuperPoint  |
| `keypoints`         | `[N, 2]`     | 2D coordinates of detected keypoints          |
| `keypoint_scores`   | `[N]`        | Confidence scores of keypoints                |
| `descriptors`       | `[N, D]`     | Local feature descriptors                     |
| `matches`           | `[K, 2]`     | Matching indices generated by LightGlue       |
| `points0`           | `[K, 2]`     | Matched point coordinates in the first image  |
| `points1`           | `[K, 2]`     | Matched point coordinates in the second image |

Here, `K` is the number of matched keypoint pairs.

For example, if:

```text
matches shape: torch.Size([141, 2])
```

it means LightGlue found 141 matched keypoint pairs between the two images.

## 9. Common Issues

### 1. `ModuleNotFoundError: No module named 'lightglue'`

Make sure the correct conda environment is activated:

```bash
conda activate lightglue
```

Then check the Python interpreter:

```bash
python -c "import sys; print(sys.executable)"
```

If LightGlue is still missing, install it again from the official repository.

### 2. `FileNotFoundError`

Check whether the input images exist:

```text
images/image0.jpg
images/image1.jpg
```

Also make sure you are running the script from the project root directory.

### 3. Very few or zero matches

Possible reasons:

* The two images do not share overlapping content
* The viewpoint difference is too large
* The image is too blurry
* The scene has too few textures
* The two images are completely unrelated

Try using two images of the same building, room, object, or scene.

## 10. Limitations

This project is only a minimal reproduction and learning demo.

It does not include:

* Training LightGlue from scratch
* Reproducing full paper benchmark results
* RANSAC geometric verification(The number of matches output by LightGlue can't be directly used as a criterion for image similarity. According to the original LightGlue paper, the model focuses on local feature correspondences and filters matches based on matchability and confidence; the paper doesn’t specify a minimum number of matches required for images to be considered similar. In architectural images, even if two images are of different buildings, a few candidate matches might still appear due to windows, edges, corners, and repeating textures. So, in this project, we’ll need to add RANSAC geometric verification later and use the number and ratio of inliers to determine if the matches are geometrically consistent.)
* Homography estimation
* Camera pose estimation
* Full visual localization pipeline
